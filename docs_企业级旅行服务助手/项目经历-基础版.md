# 企业智行 · 企业差旅智能助手　　AI应用开发（实习/学习项目）　　2026/06 - 2026/08

## 项目背景：

　　针对企业员工差旅安排分散在聊天记录和表格中、人工规划费时费力、差旅标准难以统一管控的问题，使用大模型 API 开发了一个企业差旅智能助手。用户用一句话描述出行需求，系统即可生成完整的多日行程，并支持行程管理、差旅政策检查、审批流转和航班车票实时提醒。项目采用 Python FastAPI 编写三个后端服务（智能对话、行程管理、实时监控），前端使用 React 实现工作台页面，带有登录账号和管理员配置功能。

## 主要职责：

- 使用 FastAPI 实现三个后端服务：智能对话服务（接收用户消息、调用大模型回复）、行程管理服务（行程生成、增删改查、政策与审批）、实时监控服务（航班车票天气定时检查），对外提供 40 余个 RESTful 接口。
- 实现大模型行程生成功能：通过两步提示词完成——先让大模型从用户自然语言中提取目的地、日期、人数等参数，再按预设规则（每日景点数量、通勤时长、用餐时段）生成结构化的行程 JSON，解析后存入系统。
- 实现 SSE 流式输出：后端把大模型生成的内容分段推送给前端，用户几秒内就能看到内容逐步出现；错误信息通过独立消息帧返回，与正文内容分离。
- 编写差旅政策知识库检索功能：将公司差旅政策文档入库，用户提问政策问题时先检索相关原文，再让大模型依据原文回答并注明出处，保证回答有依据；关键词检索已实现，向量语义检索框架已搭建。
- 实现差旅政策检查与审批流程：行程生成后自动对照职级差旅标准检查费用是否超标，需要审批的行程自动创建审批单并指定主管审批人，主管通过后行程才生效，拒绝则行程作废。
- 使用 APScheduler 实现实时监控定时任务，每 5 分钟检查用户订阅的航班动态、铁路 12306 车票（是否停运/无票）和天气预警，发现异常自动生成提醒；外部数据接口使用模拟数据兜底。
- 实现登录功能与管理员页面：账号密码登录（管理员和普通员工两种角色，登录后才能使用系统）；管理员可以在页面里在线切换大模型、修改接口地址和 API Key（保存后立即生效），普通员工看不到管理入口。
- 设计降级兜底方案：大模型接口不可用时使用模板生成示例行程，外部数据源无 API Key 时使用模拟数据，保证系统在不配置任何密钥的情况下也能完整运行和演示。
- 使用 React 完成前端工作台的页面（智能助手、行程列表、行程详情、实时监控、组织、政策、审批、系统管理），通过 fetch 与后端接口联调，实现流式内容的前端渐进渲染；对话回答升级为卡片式展示（行程卡可点击跳转详情），回答后推荐相关的追问问题。
- 编写 pytest 测试 60 余例，覆盖后端接口、数据存储、大模型调用和核心流程；编写种子数据脚本，保证演示环境一键初始化。

## 项目难点：

- 大模型输出的内容格式不稳定，直接解析经常失败。通过三重方式解决：提示词中明确要求只输出 JSON 并给出格式样例、解析失败自动重试一次并尝试提取文本中的 JSON 部分、仍失败则降级使用固定模板生成行程，保证了生成功能的稳定性。
- 排查中文乱码问题：大模型返回的中文在页面上显示为乱码。通过分段定位（先直接请求后端接口确认后端返回即乱码，排除前端），最终发现是 HTTP 响应未声明字符编码，浏览器按默认编码解析 UTF-8 中文导致，在响应头中补充 charset=utf-8 后解决，由此深入理解了 HTTP Content-Type 与字符编码机制。
- 接入新的大模型（小米 MiMo）时遇到三个兼容问题：它的流式返回里有特殊空帧导致解析代码报错、它会先"思考"消耗字数导致正文为空、输出的 JSON 偶尔格式不标准。通过修改统一的大模型调用封装（跳过空帧、加大字数预算、提取文本中的 JSON），上层业务代码完全不用改就完成了新模型接入。
- 保证系统在无任何外部 API 密钥的情况下完整可用：为每个外部依赖（大模型、天气、航班车票数据）都实现了兜底方案，降级逻辑封装在各数据源内部、对上层透明，功能链路在任何情况下不中断。
