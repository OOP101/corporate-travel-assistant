### 模块 1 · 登录与权限
- **功能**：账号密码登录（Token 24h）、管理员/员工角色分离、退出登录
- **技术点**：sha256+加盐口令哈希、内存 Token 签发与校验、FastAPI 依赖注入（require_admin）、浏览器防自动填充（readOnly+new-password）
- **关键文件**：`services/journey-hub/api/auth.py`、`frontend/src/pages/LoginPage.jsx`、`App.jsx`（登录门卫）

### 模块 2 · 智能对话（首页）
- **功能**：一句话规划行程（流式）、差旅问答（政策 RAG）、行程管理指令、应急协助；回答卡片 + 补充追问
- **技术点**：LangGraph StateGraph 意图路由（规则+正则分类：规划/问答/管理/应急）、invoke_stream 真流式、政策检索注入回答依据、行程/政策/审批卡片解析
- **关键文件**：`services/journey-hub/state/graph.py`（核心编排）、`router/intent.py`（分类器）、`tools/handlers.py`（plan_trip_stream / chat_query / _policy_context）、`frontend/src/pages/ChatPage.jsx`

### 模块 3 · 行程生成与管理
- **功能**：两阶段生成（参数提取→规则生成）、行程 CRUD、SSE 流式、出行清单、总结、费用统计、模板复用、应变重排、审批门禁（待审批禁改）
- **技术点**：每请求独立生成器（防并发串单）、chat_json 保护重试、状态机（pending_approval→planned/cancelled）、属主校验防 IDOR
- **关键文件**：`services/planner-core/api/routers/trips.py`、`generators/itinerary.py`、`generators/reroute.py`、`api/routers/approvals.py`

### 模块 4 · 差旅政策与审批
- **功能**：政策 CRUD 与职级匹配、费用超标检查、审批自动发起/通过/拒绝/取消、政策文档管理 + RAG 检索
- **技术点**：get_best_match 职级匹配、check_violations 规则引擎、RAG 三后端（bge 本地/API/关键词）+ 失败熔断、原文 excerpt 引用
- **关键文件**：`api/routers/policy.py`、`api/routers/approvals.py`、`api/routers/policy_docs.py`、`store/org_store.py`（PolicyStore/PolicyDocumentStore）、`shared/embedding/`

### 模块 5 · 组织管理
- **功能**：部门/员工/职级 CRUD、主管关系（审批人自动解析）、员工检索
- **关键文件**：`api/routers/org.py`、`store/org_store.py`

### 模块 6 · 实时监控
- **功能**：订阅制监控（航班/铁路 12306/天气/路况/景点）、每 5 分钟轮询、分级提醒推送、手动检查、前端订阅表单
- **技术点**：BaseSource 统一抽象（真实 API + Mock 降级）、12306 余票解析（停运/无票/有票）+ 反爬降级、APScheduler、变更检测去重、严重度分级
- **关键文件**：`services/sense-engine/engine.py`、`sources/{flight,train,weather,traffic,attraction}.py`、`api/main.py`（SubscribeRequest）、`frontend/src/pages/AlertsPage.jsx`

### 模块 7 · 系统管理（管理员）
- **功能**：可用模型列表维护、默认模型切换、LLM 服务商配置在线热更新、密钥脱敏
- **技术点**：ConfigStore 单实体存储、运行时重新注册 LLM provider（无需重启）、管理员接口 403 拦截
- **关键文件**：`services/journey-hub/api/admin.py`、`frontend/src/pages/AdminPage.jsx`

### 模块 8 · 平台底座（shared/）
- **内容**：LLMManager（多服务商注册表 + 流式 + chat_json 重试）、BaseJsonStore（JSON 存储基类，原子写+锁）、APIKeyAuth + app_factory（中间件/CORS/健康检查/HTTP 指标）、ServiceClient（重试/连接池）、SSE 封装、Prometheus 指标、结构化日志、统一配置（数据路径锚定项目根）
- **关键文件**：`shared/llm/manager.py`、`shared/store/base_store.py`、`shared/middleware/`、`shared/http_client.py`、`shared/sse.py`、`shared/config/settings.py`

## 二、四条核心数据流

**① 行程生成流**（用户说"9月15号广州飞北京出差…"）
```
前端 ChatPage → journey-hub /agent/chat/stream
  → 意图路由(计划) → preflight 校验 → plan_trip_stream 工具
    → planner-core /trips/generate (SSE)
      → 参数提取(LLM chat_json) → 规则生成(LLM chat_stream)
      → 解析 JSON → 存 TripStore → 政策检查 → 自动发起审批 → 行程置 pending_approval
  ← chunk 帧逐段透传（进度→行程摘要→政策→审批）
前端：流式渲染 + 行程/政策/审批卡片
```

**② 政策问答流**（用户问"住宿标准是多少"）
```
意图路由(chat) → 检索政策知识库(planner /policy-docs/search, 关键词降级)
  → 原文注入 prompt → LLM 流式回答（注明出处文档）→ 前端补充追问 chips
```

**③ 监控告警流**
```
订阅(车次/航班/城市) → APScheduler 每 5min check_all
  → 各数据源 check()（真实 API → 失败降级 Mock）→ SourceResult
  → 过滤(<15min 延误静默) → 变更检测去重 → AlertManager 推送
```

**④ 审批流**
```
自动创建审批单(审批人=直属主管) → 行程 pending_approval（禁改）
  → 主管 approve → 行程 planned 生效 / reject → cancelled 作废
```

## 三、代码阅读路线（学习建议）

按以下顺序读代码，每步都能跑起来验证：

1. **先跑起来**：`scripts/start_local.py` + 前端 `npm run dev`，登录 admin/admin123 走一遍演示路径
2. **看对话入口**：`journey-hub/api/main.py`（路由注册）→ `router/intent.py`（分类规则）→ `state/graph.py`（invoke / invoke_stream）
3. **看行程生成**：`planner-core/api/routers/trips.py`（SSE 路由）→ `generators/itinerary.py`（两阶段生成 + 演示降级）
4. **看公共层**：`shared/llm/manager.py`（多模型适配的精华，含 MiMo 兼容处理）→ `shared/store/base_store.py` → `shared/middleware/app_factory.py`
5. **看监控**：`sense-engine/engine.py` → `sources/flight.py` 与 `sources/train.py`（对比真实/Mock 两种实现）
6. **看测试**：`tests/` 与 `services/*/tests/`，最后跑 `scripts/e2e_verify.py` 看六项端到端检查
