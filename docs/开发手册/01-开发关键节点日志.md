## 4. 阶段四：企业化补全（09-11）

### 节点 4-1 · 景点攻略语料 RAG 通道

- `TravelGuideStore`（`data/org/guide_docs`，与 `policy_docs` 分开存储防企业/个人语料串档）+ `/guides` 路由（CRUD / search / reindex）。
- **决策**：景点语料仅 `scene=personal` 召回——商务差旅不做旅游推荐。
- 8 篇种子语料（西湖 / 灵隐寺 / 熊猫基地 / 宽窄巷子 / 故宫 / 八达岭 / 兵马俑 / 亚龙湾）；13 用例（含双语料不串档、四个企业场景不召回）。
- **踩坑（重要）**：Edit 报成功但静默未落盘 → 自此铁律「**编辑后必须 grep 回读校验，信验证不信返回值**」。

### 节点 4-2 · 身份 / 鉴权大修

- `SignedSession`：HMAC-SHA256 无状态签名 token（exp 内嵌、compare_digest）；`revoke()` 为 no-op，改 secret 即全量失效。
- `resolve_user_id()` 优先级：Bearer > 显式 session_id > workspace；属主校验只拒「声明了别人」（防 IDOR 又不误伤）。
- 测试 +13（全量 121 passed）。

### 节点 4-3 · 自助注册

- `POST /auth/register`：注册即签发 token（注册即登录）；用户名 `^[A-Za-z0-9_.-]{3,32}$`、大小写不敏感查重；保留名 `{admin, web-user, default}`（与组织侧 employee_id 同值）。
- **角色不接受客户端指定**（新账号一律 user，防自封管理员）。
- 口令 sha256 → pbkdf2-sha256 12 万轮（stdlib 免依赖）；旧记录验证通过后自动升级；比对改 `secrets.compare_digest`。
- LoginPage 登录 / 注册双模式；+29 用例（全量 150 passed）。

### 节点 6-6 · 澄清回合死循环修复（09-23）

- **用户实截反馈**：助手问「目的地是哪里 / 计划哪几天去」，用户点界面上的「你看着办，按常见差旅默认补全」后助手**原样重问同一句**——连点 5 次得 5 遍相同反问，用户原话「你看看这能使用的吗」。
- **根因（两条，代码级）**：
  1. **授权代填从未实现**：PRD §6.3 写明「随便 / 你看着办」= 对代填的显式授权，但全仓搜不到任何授权识别逻辑。用户点了按钮，抽参结果与点之前**完全一致**（`missing` 仍为 `['destination','start_date','days']`）→ 同一句反问原样重现。

- **修复**：

### 节点 6-10 · 类型化决策层 `shared/decision`（09-24）

- **由来**：调研 System One（TypeSafe AI 的「类型化决策」模型）后，选「镜像范式、不引外部依赖」的落地路径——把「非结构化状态 + 类型化问题 → 类型化答案 + 置信度」的判定能力，接到已有 TokenHub 上，用于替代散落的**关键词正则**与 LLM-as-judge。
- **新增包 `shared/decision/`（4 个文件，与 `shared/llm/` 平级）**：
  - `types.py` —— 忠实镜像 `typesafe_sdk` 的三种原语：`Noul`（是/否，答案 `noul∈[0,1]` 就是「是」的概率）、`Choice`（命名选项 + 置信度 + 概率分布）、`Score`（有序评分表 + 档位概率 + 图例）；答案侧 `NoulAnswer/ChoiceAnswer/ScoreAnswer` + `DecisionResponse`（`nouls/choices/scores` 分视图）。
  - `client.py` —— `DecisionClient.system_one(state, questions, model)`：提示词 JSON 模板 + 结构校验 + 概率归一（**先归一后截断**，否则模型给「权重式」输出 `{2.0, 1.0}` 会被截成 1:1 抹掉偏好）+ 畸形输出纠正重试（把失败原因回灌给模型）+ `DecisionError` 收敛。别名 `SystemOneAdapterClient` 对齐官方命名。
  - `guard.py` —— **业务真正需要的形态**：`ask_noul/ask_choice/ask_score` 客户端不可用 / 抛异常 / 落在不确定带 → 一律回 `default`，**绝不抛出**；判定值带 LRU 缓存，重复文本（用户连点同一个按钮）第二次起零成本。
  - `__init__.py` —— 公共 API 对齐官方 `system_one_adapter` 的导出面。
- **接入点（首个）：`itinerary.is_autofill_authorized` 改两级判定**：关键词正则快路径（命中即返回，行为不变）→ 未命中且传入 `decision` 时补一次类型化判定。`_extract_params` 侧**三重门控**（`carry` 非空 = 澄清回合 / ≤24 字 / 正则未命中），首轮完整需求句与长句都不付这次往返。
- **实测（`scripts/probe_decision.py`，deepseek-v4-flash 真机）**：
  - 三种原语单发成功，`in=585 out≈315`，约 4.5 秒；判定类任务 `temperature=0`。
  - 授权识别矩阵 10 例：纯正则 **6/10** → 加语义兜底 **10/10 且零误判**（兜住「不用问我了 / 你帮我定就行 / 这些你拿主意吧 / 按你说的来」，未误伤「下周三去深圳出差 3 天」「下周去上海」「3 天」）。
  - 首轮判据过宽时曾把「下周三去深圳出差 3 天」误判为授权 → 判据补「**出现具体日期/天数/目的地/人数/预算一律判否**」后归零。
  - 对照实验：`llm_answer_mode="discrete"` 既**更慢**（3.2s）又**更差**（2 例误判）→ 保持默认 `probabilities`。
- **默认关闭**（`DECISION_SEMANTIC_AUTOFILL=0`）：准确率已达标，但单次判定平均 **~2.7 秒**，而 UI 那枚按钮的原话正则本就命中；不给每轮澄清都加 2.7 秒，需要时一个环境变量打开。测试基线 230 → **258 passed**。

## 附录 C · 踩坑速查（按主题）

> 本节记**开发工具链 / 环境 / 接口层**的坑；业务与架构级的坑见 [`../项目文档.md`](../项目文档.md) 第八节「踩坑记录」。两者颗粒度不同，不重复。

**工具链**
- Edit 可能报成功但未落盘（EBUSY 竞态）→ 每次修改后 grep 回读校验。
- bat 必须 CRLF + 纯 ASCII；Write 默认写 LF，写完用 Python 读字节复验。
- `.gitignore` 不支持行内注释。
- 根目录清杂物前先查引用（bench_models.json 差点误删——抗打假证据）。

**环境**
- 沙箱按进程树回收服务（agent 拉起的服务活不过命令结束）→ 未经用户要求不主动 start；常驻靠用户双击 start.bat。
- 本机代理劫持 localhost → `trust_env=False`。
- Git Bash 缺 coreutils → 目录/文件操作用受管 Python。
- pytest 临时目录网络路径报错 → `--basetemp=./.pytest_tmp`。

**代码 / 接口**
- ServiceClient 每请求新建 session（keep-alive 半关连接复用致偶发 404）；post 无 timeout 参数。
- 三服务同名顶层 `api` 包 → 服务内一律相对导入。
- FastAPI 422 与 Optional 参数；中文乱码 ISO-8859-1。
