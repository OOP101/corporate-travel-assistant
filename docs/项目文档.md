## 一、项目概述

面向企业内部的智能行程规划与安排平台，以 LLM 为大脑、以多源实时数据为感知，覆盖「行前规划 → 行中保障 → 行后归档」全链路，服务于员工差旅、客户拜访、会议参展、团队出行等企业内部行程场景。

三个松耦合服务（行智 Journey Hub / 策程 Planner Core / 感知 Sense Engine）+ shared 公共层，**单体模式（默认）单进程单端口 8001，一键切换微服务模式**。

---

## 二、项目背景

企业行程安排分散在邮件、IM、Excel 中，员工差旅需自行查交通/天气/政策，行政人力成本高。本项目用多 Agent 协作重构差旅流程：

1. **行前规划**：自然语言 → 结构化行程（交通/住宿/会议/拜访/餐饮），含出行清单与预算
2. **行中保障**：航班延误/天气/路况主动推送，突发应变重排
3. **行后归档**：行程总结 + 费用统计 + 复用模板
4. **合规闭环**：差旅政策 RAG 检索 → 政策检查 → 审批流转

## 四、技术栈

| 层次 | 技术选型 |
|:---|:---|
| Web 框架 | FastAPI + Uvicorn |
| AI 编排 | LangGraph (StateGraph) |
| LLM 调用 | 腾讯 TokenHub `deepseek-v4-flash`（主）/ `kimi-k3` / `hy-mt2-pro` / `hy-mt2-lite`，OpenAI 兼容多模型适配，管理端配置切换（改默认模型后重启生效） |
| 向量检索 (RAG) | Embedding 可插拔：本地 `BAAI/bge-large-zh-v1.5` 或 OpenAI 兼容；不可用时自动降级关键词检索 |
| 前端 | React 19 + Vite 8 + Tailwind CSS 4 + React Router |
| 定时调度 | APScheduler（5 分钟轮询） |
| 外部数据 | 腾讯位置服务（SN 签名）+ 和风天气 + 12306 |
| 可观测性 | Prometheus + 结构化 JSON 日志 + 全链路 Trace |
| 容器化 | Docker + Docker Compose |

> **LLM 通道**：2026-09-17 已全量切换腾讯 TokenHub，主模型 `deepseek-v4-flash`。思考模型（kimi-k3）强制 temperature=1，已在 `shared/llm/manager.py` 按模型名自动处理。

## 六、架构设计

**三服务架构**：

```
前端工作台 3001 ──▶ 统一网关 8001（单体模式）
                    ├── /        行智 Journey Hub（Agent 编排）
                    ├── /planner 策程 Planner Core（行程规划）
                    └── /sense   感知 Sense Engine（实时监控）
```

微服务模式则三服务各自独立进程占 8001/8002/8003。

**核心设计**：
- **S0–S6 七态状态机** + explicit > 规则正则 > LLM（含 carry 上下文继承）参数提取，商务类场景模板直出（生成阶段 0 LLM，宁慢勿错回退大模型）
- **SSE 结构化帧协议**（progress/chunk/respond/error），进度首帧 0.1s
- **trip_saved 帧平铺行程要素**（origin/destination/dates/attractions/weather/transport），前端收到后自动订阅 sense 监控
- **单/微双形态装配**：别名包 + AsyncExitStack 三 lifespan，业务零复制
- **腾讯地图 SN 签名**：`sig=md5(路径?升序参数+SK)`，lat,lng 与高德相反
- **铁律**：无凭证绝不编造数据，外部 key 空或调用失败一律返回 None

## 八、踩坑记录

1. **v1 臆造行程（最经典）**：「我下周要去深圳」→ 直接生成「深圳3天文化之旅」+ 自动审批。根因：extract prompt 示例即默认值 + setdefault 兜底 + 无澄清确认 → PRD v2 全链路重写为澄清式状态机（澄清≤2轮 → 草案 → 用户确认 → 才落库审批）。
2. **中文乱码 `æ·±å³`**：requests 对无 charset 的 text/* 按 ISO-8859-1 解码 → 三处补 charset=utf-8 + 历史数据 latin-1 roundtrip 修复。
3. **并发串单**：全局生成器单例被改 model + 共享 `_last_trip` → 每请求独立实例 + 并发回归。
4. **数据孤岛**：.env 相对路径 + 服务各自 cwd → 数据写散 → `_anchor_data_path` 锚定项目根 + 迁移 36 文件。
5. **实时监控"失效"**：订阅/提醒纯内存态重启即空 → 落盘原子写 + RLock + 单行程上限 200 条。
6. **思考模型三类差异**：空 choices 帧 IndexError、思考耗 max_tokens 致空正文（抬到 2048）、JSON 瑕疵重解析。
7. **personal 政策误命中**：非员工 level="" 命中通用政策哑雷 → `_POLICY_EXEMPT_SCENES` 短路。
8. **.env.bak 泄漏**：备份文件推上公开 GitHub → git rm --cached + .gitignore 堵 + key 轮换。
9. **bat 编码**：中文注释/GBK 输出反复出事 → 约定 bat 永远 CRLF + 纯 ASCII。
10. **流式首帧耗时**：旧 bench（MiMo 系）首 chunk 3.6~178s（实测上限 177.4s，2026-09-18 裁定统一写 178），是「流式是必需品不是优化」的论据；切换腾讯 TokenHub 后 hy-mt2-pro 实测首 chunk ~1.1s、全程 3.9~4.2s；进度首帧 0.1s 缓解体感。2026-09-18 进一步结构性提速：商务类场景模板直出后，典型差旅句式「提取+生成」0ms、全链路 0 次 LLM（改造前同句式总耗时 19.2s）。

## 快速开始

详见 [`README.md`](../README.md)。核心入口：

```bash
python launcher.py            # 默认单体启动：单进程单端口 8001
python launcher.py micro      # 微服务模式（8001/8002/8003）
python launcher.py stop       # 停止全部
```

或直接双击 `start.bat`（启动）/ `停止.bat`（停止）。
