## 三、问题清单（每条带证据）

### 🔴 P0 —— 正确性 / 真实性

**P0-1｜行程核心数据裸写，简历宣称的原子写只覆盖了一半**
- 证据：`shared/store/base_store.py:112-120` 有 `temp + os.replace` 原子写；但 `trip_store.py:107-113` 是**裸 `open("w") + json.dump`**——行程是全系统核心实体，崩溃即损坏；`profile_store.py`、`template_store.py` 同样裸写。
- 影响：①简历第六节「修复 JSON 存储非原子写损坏问题（temp + os.replace 原子写）」**只对 org 系成立**——2026-09-18 简历与面试素材已同步限定为「BaseJsonStore 体系存储」（技术详解 Q8 附面试标准答案），P0-1 完成后可放开；②行程数据损坏风险真实存在。
- 动作：TripStore / ProfileStore / TemplateStore 迁移到 BaseJsonStore（org 系已有迁移先例，存量数据兼容写迁移函数），预计半天。

**P0-2｜测试盲区 16 端点**
- 证据：policy_docs 7 / reimbursements 6 / reports 3 全部零测试引用（实测 09-18）；org 5/10。
- 影响：P2 功能（报销 / 报表 / 政策文档）改一处坏三处无回归报警；简历「pytest E2E 回归」覆盖面被代码现状限制。
- 动作：补 3 个测试文件（~20 用例，对齐 test_planner_api.py 风格），预计一天。

**P0-3｜LLM 网关注册代码双份**
- 证据：`journey-hub/api/main.py:93-115` 与 `planner-core/api/main.py:75-97` 逐行近似（同一注册块 + 同一 route 循环）；2026-09-17 切 TokenHub 时**同一段代码改了两处**（工作区在途改动实证）。
- 动作：下沉 `shared/llm/bootstrap.py::register_llm_from_settings(llm)`，两服务各留一行调用，预计 1~2 小时。
